# 精确归因框架——实验协议

- **文件：** `experiment_protocol.md`
- **版本：** 1.0-draft
- **状态：** 初始实验协议；具体参数可由试验结果修订
- **最后更新：** 2026-11-09
- **项目：** 进化归因

## 1. 实验目的

验证框架能否在已知机制的合成模块系统中，使用受控干预恢复单模块效应、模块交互和指定价值函数下的贡献分配，并正确表达估计不确定性。

本协议评估的是归因方法，不是自动演化能力，也不是某个特定 Harness 的性能。

## 2. 基本实验单位

每次运行至少关联：

- 场景 ID 与版本；
- 任务实例 ID；
- 系统配置及模块状态；
- 干预 ID、目标模块和干预语义；
- 随机种子及随机流策略；
- 软件版本、配置摘要和运行时间；
- 结果指标、模块轨迹、异常与运行状态。

同一对比中的任务实例应尽可能匹配。随机性可控时，应使用配对种子或共同随机数，并记录其使用依据。

## 3. 合成场景设计

V1 至少包含以下场景族。具体系数、任务数量和噪声水平作为场景配置保存，不应硬编码进估计器。

### 场景 A：独立模块效应

各模块对结果产生可加的独立影响，不包含交互。用于验证单模块效应估计是否准确，以及在无交互时是否能避免虚构协同。

### 场景 B：模块交互

至少设置正向协同和负向拮抗交互。用于验证差分中的差分估计能否恢复交互方向和大小，并检查仅依赖单模块消融是否会遗漏背景依赖。

### 场景 C：正负贡献并存

设置有正向、负向及接近零效应的模块，并允许不同背景下效应发生变化。用于检验排序、符号识别和平均效应解释是否可靠。

### 场景 D：随机噪声

在已知效应结构上加入可控噪声，设置多个噪声水平。用于检查配对设计、不确定性区间覆盖率及估计精度随噪声变化的行为。

### 后续扩展场景

可加入模块依赖、不可执行联盟、非线性结果指标、高阶交互和跨任务域异质性。它们用于压力测试，不应取代 V1 的基础场景。

## 4. 实验阶段

### 阶段 1：基线运行与单模块消融

1. 运行所有模块启用的基线配置；
2. 对每个模块分别实施预先声明的消融；
3. 在匹配任务实例和适当配对种子下重复运行；
4. 计算各背景配置下的条件干预效应；
5. 报告点估计、不确定性和样本量。

注意：单模块消融只回答其指定背景下的干预对比，不应被直接解释为模块在所有配置中的固定贡献。

### 阶段 2：组合干预与交互估计

对模块对进行组合实验，至少覆盖四种状态：`(0,0)`、`(1,0)`、`(0,1)`、`(1,1)`。在背景状态固定时计算差分中的差分。

小规模系统在可行时运行完整 `2^n` 全因子设计。若只运行部分组合，必须说明抽样设计、未观测组合及其对可识别性的影响。

### 阶段 3：贡献分配

明确联盟价值函数 `v(S)`、任务总体、结果指标和干预语义。对小规模系统收集所有联盟价值并精确计算 Shapley 值。若联盟不可执行，应标记未定义或采用预先论证的替代机制，不得静默插补。

贡献分配结果必须与条件干预效应、交互效应分开报告。

## 5. 干预语义规范

每次干预必须明确属于：绕过、空输出、中性替换、替代实现，或其他有明确定义的干预。

实验配置至少记录：目标模块、干预类型、替代组件/参数、输入输出接口约束、受影响的下游模块、执行是否成功，以及任何结构变化。

如果模块关闭导致接口错误、下游跳过或执行路径变化，应将其作为实验结果和限制记录，不能把所得差异简单归因于模块本身的功能贡献。

## 6. 重复运行与不确定性

- 每个实验条件执行足够重复次数；重复次数应由预实验方差和目标精度确定，不预设一个适用于所有场景的固定数字。
- 比较条件尽量共享任务实例；适用时使用配对随机种子。
- 先计算匹配区块内的效应差，再跨区块汇总。
- 报告均值/点估计、标准误或区间、重复数、任务数和失败运行数。
- 分析任务间变化与同一任务内随机变化；条件允许时分别估计。
- 不得把“未检测到显著效应”写成“真实效应为零”。

## 7. 真值隔离与验证流程

建议采用以下流程：

1. 场景生成器创建任务和隐藏机制真值；
2. 执行器只获得运行所需配置，不向估计器暴露隐藏参数；
3. 记录器保存观测结果和干预元数据；
4. 估计器仅读取允许公开的记录并生成归因结果；
5. 冻结估计结果及其版本/摘要；
6. 验证器读取隐藏真值，计算误差和校准指标；
7. 报告器同时呈现估计与验证结果，并明确两者边界。

开发调试用场景、参数和随机种子应与最终验证集隔离。最终验证真值不得用于同一轮最终估计器调参。

## 8. 数据记录规范

原始运行记录建议采用 JSONL 追加写入。每条记录应包含：

- `run_id`、`experiment_id`、`scenario_id`、`task_id`；
- `system_config_id`、模块启用状态；
- 干预目标、干预类型和干预参数；
- 随机种子、随机流策略、重复编号和配对区块 ID；
- 原始结果指标及模块级轨迹；
- 运行状态、异常信息、时间戳；
- 代码版本、依赖版本和配置摘要。

真值数据应存放在估计器无权访问的独立位置或接口中。分析产物应引用原始记录，不覆盖原始记录。SQLite 可作为查询索引，但不是原始证据的唯一副本。

## 9. 评价指标

**主效应与交互效应：** 有符号偏差、MAE、RMSE、符号识别准确率；必要时报告排序相关性。

**贡献分配：** 对已知价值函数所对应 Shapley 值的误差、总和一致性和排序稳定性。

**不确定性：** 区间覆盖率、平均区间宽度、不同噪声水平下的校准。

**稳健性：** 未见任务实例、未见机制参数、不同随机种子、不同模块数量及依赖结构下的表现。

不得仅凭单一汇总分数判断方法有效；应同时报告分场景结果和失败案例。

## 10. 最低验收标准

V1 至少应证明：

1. 一个端到端合成实验可以从配置执行到结果报告；
2. 原始实验记录完整且可追溯；
3. 单模块消融估计在独立效应场景中恢复已知效应；
4. 组合干预能在交互场景中识别协同与拮抗方向；
5. 小规模联盟价值可用于精确计算 Shapley 分配；
6. 估计器无法访问模拟真值，验证器可在结果冻结后独立验证；
7. 在随机噪声下报告合理的不确定性，而非只输出单点分数；
8. 测试覆盖干预语义、无效联盟、异常运行和真值隔离边界。

具体数值阈值应在预实验后根据场景难度和噪声水平确定，并在设计历史中记录依据，不应事先任意指定。

## 11. 实验报告模板

每份报告至少包括：研究问题；场景与机制类别（不向估计器泄漏真值）；任务总体；模块与依赖关系；干预语义；实验矩阵；样本量和随机策略；效应估计与区间；验证误差；失败/无效运行；已知限制；代码与配置版本；下一步待检验假设。

## 12. 与 baseline 的对比边界

如未来进行 baseline 对比，应把它作为独立外部方法，清楚记录双方输入、预算、任务集和评价口径的可比性限制。不得为了复现 baseline 内部实现而改变本框架的核心架构，也不得将 baseline 的内部指标或流程未经论证地当成本项目归因定义。
